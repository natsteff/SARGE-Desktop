# SARGE Desktop project instructions

## Release documentation and screenshots

- For every published release, update the root README latest-release version label and download link, plus the version heading and release link in desktop/README.md. Do this even when other README content or screenshots are on hold. Verify the linked release exists.
- Publish the Windows release before requesting new screenshots: Nate must install the published build on his PC to capture them. Never ask whether to refresh screenshots during publication or make screenshots a release gate.
- Assess screenshot needs independently before asking Nate. Skip the question for changes without visible UI impact, minor cosmetic changes, or changes that leave existing screenshots useful and accurate. Do not ask routinely for every release.
- Only when a meaningful UI/workflow change makes existing screenshots misleading or leaves an important new workflow uncovered, explain the specific gap and ask whether to update docs/SCREENSHOTS.md with a focused capture plan. Honor a decision already given. This planning decision must not delay publication.
- Screenshot capture, review and README image publication are a separate event after the Windows release is available and testing/captures are provided. Request only the agreed views; do not automatically start a capture assignment with each release.
- Keep existing screenshots accurately labeled with the version they actually show; never relabel old captures as a newer release.
- Update broader README content and screenshots only within the user's authorized scope.

## Change queue

- Collect requested changes in a queue without implementing them until the user explicitly says to proceed. Keep adding subsequent items to that queue.
